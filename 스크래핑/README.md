# RICKY 소싱 리서치 파이프라인

한국 인기도 신호 × 캐나다 공식몰 신제품 × CA/KR 가격 비교를 자동화한다.
PROJECT.md §6(공급처 모니터링)의 **상류 단계** — 이미 등록한 SKU를 감시하는 게 아니라,
**무엇을 팔지 발굴**하는 단계다.

```
[1] 한국 인기도 신호      네이버 블로그·카페 언급량 + 검색어 트렌드 (API HUB)
        ↓
[2] 캐나다 공식몰 카탈로그  사이트맵(lastmod) → 신제품 판정 → JSON-LD로 가격·재고·variant
        ↓
[3] 매칭                  상품코드 정확 매칭 → 실패 시 한/영 토큰 유사도
        ↓
[4] 한국 가격             브랜드 한국 공식몰 정가
        ↓
[5] 리포트                마진 산출 → 소싱 우선순위 (Markdown + CSV + JSON)
```

---

## 준비

```bash
cd 스크래핑
npm install
npm run browsers                   # Playwright Chromium

# WSL/리눅스는 시스템 라이브러리가 추가로 필요하다 (1회, sudo)
sudo npx playwright install-deps chromium
#  또는: sudo apt-get install -y libnss3 libnspr4 libasound2t64

cp .env.example .env               # 네이버 API 키 입력
```

### 네이버 API 키 — 2026년 이관 주의

네이버가 검색·데이터랩 API 를 개발자센터에서 **NAVER API HUB(네이버 클라우드)** 로 옮겼다.
그래서 developers.naver.com 애플리케이션 등록 화면의 "사용 API" 드롭다운에는
**검색·데이터랩이 나오지 않는다.** 목록에 없는 게 정상이며, 신규 발급은 HUB 에서 받는다.

| API | 상태 |
|---|---|
| 블로그·카페글·뉴스 검색 | API HUB 로 이관 |
| 검색어 트렌드(데이터랩) | API HUB 로 이관 |
| **쇼핑 검색** | **2026-07-31 종료 · 공식 대체 없음** |

- 신규 발급: https://www.ncloud.com/product/applicationService/naverApiHub
  → `.env` 의 `NAVER_HUB_KEY_ID` / `NAVER_HUB_KEY`
- 기존 developers.naver.com 키가 있으면 **2027-06-30 까지** 그대로 쓸 수 있다
  → `.env` 의 `NAVER_CLIENT_ID` / `NAVER_CLIENT_SECRET`

둘 중 무엇이 설정됐는지는 코드가 자동 판별해 도메인과 인증 헤더를 바꾼다.
`npm run doctor` 가 실제로 한 번 호출해 키가 통하는지까지 확인한다.

**쇼핑 검색 종료의 영향** — 국내 "최저가" 축이 사라졌다. 국내 가격 비교는
브랜드 한국 공식몰 정가만 쓴다. 인기도 점수는 유통폭(commerce) 축을 빼고
남은 가중치를 재정규화하므로, 축이 없다고 점수가 깎이지는 않는다.

## 재고 조회 (색상 × 사이즈)

캐나다 공식몰의 **variant 단위** 재고를 조회한다 (PROJECT.md §6).
상품 하나가 아니라 색상 × 사이즈 조합 하나하나가 수집 단위다 — 실제 매입이 일어나는 단위이기 때문이다.

```bash
npm run stock:all   # ← 평소엔 이것만. 등록된 상품만 조회하고 북마클릿 수집분까지 합친다
```

**조회 대상은 상위 프로젝트 카탈로그다** (`src/lib/catalog.generated.ts`).
감시 목록을 손으로 관리하면 반드시 카탈로그와 어긋난다 — 상품을 등록해도 조회에 안 들어가고,
뺐는데 계속 조회한다. 등록된 상품이 곧 조회 대상이 되게 했다.

연결 고리는 **SKU 접두어에 들어 있는 브랜드 상품코드**다.

| 브랜드 | 카탈로그 SKU | 상품코드 | 공식몰 URL 에서 |
|---|---|---|---|
| 아크테릭스 | `X000010932-GRAPHITE-BLACK` | `X000010932` | 뒤 4자리 `…-0932` |
| 폴로 | `100066198-CAMEL-MELANGE` | `100066198` | `/100066198.html` |
| 코치 | `CDZ42-BRASS-MAPLE` | `CDZ42` | `/CDZ42.html` |
| 룰루레몬 | `LULULEMON-FLAMINGO-FUN` | 없음 | 이름으로만 대조 |

사이트맵을 브랜드당 한 번 읽어 URL 을 찾고 `data/supplier-urls.json` 에 남긴다.
매 실행마다 4만 건짜리 XML 을 다시 받을 이유가 없다.
북마클릿으로 받은 상품의 URL 도 여기 학습된다 — 사이트맵이 막힌 브랜드는 이게 유일한 출처다.

실측: 카탈로그 48건 중 35건 수집(아크테릭스 24 · 코치 8 · 폴로 3), URL 해석 31건 + 북마클릿 학습 4건.

목록수집이 주변 상품까지 담아 와도 **등록된 상품만 남기고** 나머지는 버린다.
그리고 아직 못 받은 상품을 리포트 상단에 띄운다 — 다음에 무엇을 할지 그게 정해 준다.

카탈로그를 무시하고 사이트맵에서 훑어보려면(탐색용):

```bash
npm run stock:scan     # = stock --all --no-catalog
```

`data/index.html` 이 **고정 주소 대시보드**다. 즐겨찾기에 걸어 두면 항상 최신 리포트로
들어갈 수 있고 지난 이력도 한 표에서 훑을 수 있다. 실행할 때마다 갱신된다.

개별로 돌릴 수도 있다.

```bash
cp watchlist.example.txt watchlist.txt   # 감시할 상품 URL 을 적는다
npm run stock -- --watch                 # 자동 수집만 (아크테릭스·코치)
npm run stock -- --import                # 북마클릿 수집분만 (폴로·룰루레몬·캐나다구스)
npm run stock -- --brand=arcteryx --limit=10   # 카탈로그 최신순 N개
```

산출물은 `data/재고-{타임스탬프}.{html,md,csv,json}` 네 벌 + 고정 주소 `data/index.html` 이다.
실행할 때마다 **직전 스냅샷과 대조해 변화를 뽑는다.**

**HTML 리포트가 기본 보기다.** 실행하면 브라우저에서 열 경로가 출력된다
(WSL 이면 `\\wsl.localhost\...` 형태). 마크다운은 매트릭스가 커지면 읽기 어렵고
필터가 없어서, 상품이 몇 개만 넘어가도 HTML 쪽이 훨씬 낫다.

- 브랜드 칩 · 검색(상품명·코드·색상) · "품절 있는 상품만" 필터
- 색상 × 사이즈 격자, 칸에 마우스를 올리면 SKU·가격
- 변화(품절·재입고·가격변동)를 유형별 색으로 상단에 배치
- 상품 카드 접기/펼치기, 다크 모드 자동
- 외부 의존 없는 파일 하나 — `file://` 로 바로 열린다

```
| 유형      | 상품                    | 색상   | 사이즈 | 변화                          |
| 품절      | Proton Heavyweight Hoody | Azalea | S     | in_stock → out_of_stock       |
| 재입고    | Beta Jacket Men's       | Black  | XS    | out_of_stock → in_stock       |
| 가격 인상 | Denim Hooded Zip Jacket | Khaki  | XXL   | CA$120.00 → CA$167.50 (+47.50)|
```

마크다운 리포트는 색상 × 사이즈 격자로 그린다 (● 재고 · ◐ 임박 · ○ 품절 · · 미편성).

```
| 색상 \ 사이즈 | XS | S | M | L | XL | XXL | XXXL |
| Black         | ●  | ● | ● | ● | ●  | ●   | ●    |
| Sea Salt      | ●  | ● | ○ | ● | ●  | ●   | ●    |
```

### 차단 브랜드는 반자동으로 — 북마클릿

룰루레몬·캐나다구스·폴로는 봇 차단으로 자동 수집이 안 된다(아래 실측 참조).
자동화로 뚫는 대신 **운영자가 평소 쓰는 브라우저로 보고 있는 페이지**에서 데이터를 걷어 온다.
진짜 사람이 진짜 브라우저로 보는 것이므로 탐지가 성립하지 않고 약관 문제도 없다.

**북마클릿이란** — 주소 대신 코드가 든 즐겨찾기다. 보통 북마크는 클릭하면 그 사이트로
이동하지만, 북마클릿은 **지금 보고 있는 페이지에서** 코드가 실행된다. 페이지 이동은 없다.

```bash
npm run bookmarklet          # 설치 페이지 생성 (한 번만)
```

출력된 경로의 HTML 을 크롬에서 열고, **두 버튼을 북마크바로 끌어다 놓는다**
(북마크바가 안 보이면 `Ctrl+Shift+B`).

| | 목록수집 | 재고수집 |
|---|---|---|
| **어디서** | 카테고리 · 검색결과 · 위시리스트 | 상품 상세 페이지 |
| **한 번에** | 그 목록에서 **카탈로그 등록 상품만** | 상품 1건 |
| **시간** | 상품당 약 7초 (34건이면 5분) | 즉시 |
| **쓰는 때** | **평소 점검.** 눌러 두고 기다리면 된다 | 매입 직전 한 상품을 정확히 |

상품마다 북마크를 누르게 하면 하루 30번을 눌러야 하고, 그러면 결국 안 쓰게 된다.
그래서 목록수집이 기본이고, **브랜드당 한 번이면 된다.**

`npm run bookmarklet` 이 카탈로그 상품코드를 북마클릿에 심는다. 전체보기 목록에서
누르면 수백 건 중 **등록된 상품만 골라 담는다** — 실측(코치 여성 전체보기):
상품 링크 34건 중 카탈로그 상품 5건만 수집했다. 다 받아 봐야 대조 단계에서 버려진다.

목록을 끝까지 스크롤해야 한다. 화면에 뜬 상품만 HTML 에 있기 때문이다.
카탈로그가 바뀌면 `npm run bookmarklet` 을 다시 돌려 북마클릿을 갱신한다. 카테고리 페이지에서 한 번 누르면 상품을 하나씩
**같은 출처 iframe 으로 띄워 실제 렌더링한 뒤** 읽는다 — fetch 로 HTML 만 받으면
화면 상태(품절 버튼)를 알 수 없기 때문이다.

수집이 끝나면 파일 하나가 저장된다. 마지막에 한 번만:

```bash
npm run stock:all                         # 자동 수집분과 함께 리포트 하나로
npm run stock -- --import=/경로            # 북마클릿 수집분만
```

> 실측(코치 카테고리): 상품 50건을 찾아 34건으로 정리한 뒤 912 variant 를 수집했다.
> 앵커 태그로는 0건이었다 — 요즘 목록 페이지는 JS 로 그리므로 HTML 본문까지 훑는다.
> 다국어 사이트는 같은 상품의 `/fr/` 판과 언어 접두어 없는 판이 섞여 중복이 나므로
> 현재 페이지 언어와 다른 URL 은 버린다.

> 북마클릿은 JSON-LD **원문**과 **화면에서 읽은 사이즈 상태**를 담아 온다.
> 해석은 `--import` 쪽 추출기가 한다 — 수집 경로가 둘이어도 해석은 한 곳에서만 해야 갈라지지 않는다.

#### 색상이 6개를 넘으면 사이즈가 사라진다 (랄프로렌)

실측한 규칙이다.

| 색상 수 | JSON-LD 사이즈 |
|---|---|
| **≤ 5** | 모든 색상에 있음 (100066198: 3색 → 정상) |
| **≥ 6** | **하나도 없음** (625239: 11색 → 색상 정보만) |

그래서 같은 브랜드인데 어떤 상품은 매트릭스가 다 차고 어떤 상품은 한 색만 찬다.
6색 이상인 상품은 목록수집이 iframe 안에서 색상을 눌러 가며 읽는다.

**색상 클릭이 다른 상품으로 이동하면 즉시 멈춘다.** 코치는 색상 클릭이
`reagan-penny-loafer/CAP31` → `reagan-loafer/CCN27-CBD` 로 넘어간다.
그대로 읽으면 다른 상품의 사이즈를 이 색상 것으로 기록하게 된다 — 없는 재고를 만드는 셈이다.

이 순회는 **iframe 안에서만** 한다. 사용자가 보고 있는 탭에서 클릭하면 페이지가 넘어가
수집이 통째로 날아간다. 그래서 단건 수집(재고수집)은 색상을 돌지 않는다 —
색상은 사람이 고르고 누르는 게 맞다(여러 번 눌러도 합쳐진다).

#### JSON-LD 를 못 믿는 사이트가 있다

두 소스가 서로 다른 방식으로 불완전해서, 덮어쓰지 않고 **합집합**으로 병합한다.

| 사이트 | JSON-LD | 화면 |
|---|---|---|
| **랄프로렌** | 사이즈를 일부만 실음 (한 색상에 S·M 둘만), 재고는 전부 `InStock` | 전 사이즈 + 실제 품절 상태 |
| **코치** | 6사이즈 전부 + 정확한 품절 상태 | 살 수 있는 버튼만 그림 (품절은 아예 안 보임) |

- 화면에 있는 사이즈 → **화면의 재고 상태가 이긴다** (실제로 보이는 것이므로)
- JSON-LD 에만 있는 사이즈 → **그대로 둔다** (화면에 없다고 없는 게 아니다)
- 선택되지 않은 색상 → **건드리지 않는다** (화면에 안 떠 있으니 알 수 없다)

리포트는 이 셋을 구분해 그린다.

| 기호 | 뜻 |
|---|---|
| `●` `○` | 재고 있음 / 품절 — 확인된 값 |
| `·` | 미편성 — 그 색상에 그 사이즈가 애초에 없다 |
| `?` | **미확인** — 사이즈 정보를 못 받았다. 재고가 없다는 뜻이 아니다 |

`?` 를 `·` 로 그리면 재고가 멀쩡한 색상이 "살 수 없음"으로 보인다.

**모르는 것은 재고로 세지 않는다.** 랄프로렌은 사이즈를 안 실어 준 색상 전용 행에도
`InStock` 을 적어 보낸다. 그대로 세면 사이즈를 하나도 못 받은 상품이 `재고 24/24` 로
찍힌다(실측 사고: 638616, 16색 중 1색만 사이즈가 옴). 그래서 헤더 숫자는 **확인된
variant 만** 세고, 나머지는 `미확인 15색` 배지로 따로 보여 준다.

#### 수량 드롭다운의 "1" 은 사이즈가 아니다

랄프로렌 페이지의 수량 선택이 사이즈처럼 생겨서 매트릭스에 `1` 열이 생긴 적이 있다.
북마클릿과 import 양쪽에 같은 사이즈 토큰 규칙을 둔다 — 북마클릿을 고쳐도
**사용자가 재설치하기 전에 만든 캡처가 계속 들어오기** 때문이다.
숫자 사이즈는 신발 치수 범위(5~15)로 좁힌다.

### 사이즈를 어디서 읽는가

브랜드마다 사이즈가 든 자리가 다르다. `src/stock/normalize.ts` 가 이 차이를 흡수한다.

| 대상 | size 필드 | 실제 사이즈 |
|---|---|---|
| Arc'teryx 전 품목 | `"XS"` … `"XXXL"` | size 필드가 정본 |
| Coach 의류 | `"M"` | size 필드 = SKU 토큰 |
| **Coach 신발** | `"extra wide"` (폭 라벨) | **SKU 안에만** — `CCN27 CBD  9.5 D` → `9.5 D` |
| Coach 가방·지갑 | `"large wristlet"` (분류 라벨) | 사이즈 개념 없음 → `-` |

Coach 신발에서 size 필드만 믿으면 9.5 와 10 이 똑같이 "extra wide" 로 뭉개져
사이즈별 재고 조회가 성립하지 않는다. 그래서 SKU 를 파싱해 치수와 폭을 되찾는다.

### 같은 색상·사이즈가 둘 이상일 때

Coach 는 스타일코드가 다른 관련 상품을 한 페이지에 묶어 둔다.
Reagan Penny Loafer 페이지에는 `CAP31` / `CCN27` / `CW699` 세 스타일이 들어 있고,
`CAP31`의 "Black 7 D"와 `CW699`의 "Black 7 D"는 **재고가 서로 다르다.**
그래서 (색상, 사이즈)가 겹치면 스타일코드로 먼저 갈라 매트릭스를 여러 개 그린다.
하나로 뭉개면 한 쪽이 조용히 사라진다.

### 아크테릭스는 시즌마다 상품코드가 바뀐다

원본 폴더 `아크테릭스/남성/Beta Jacket Men's` 안에 두 시즌 이미지가 함께 있다.

```
F26-X000010878-Beta-Jacket-Black-Front-View.avif    ← 카탈로그가 물고 있는 코드
S26-X000010511-Beta-Jacket-Headwaters-Hood.avif     ← 사이트맵에 있는 코드
```

URL 은 코드 끝 4자리로 대조하는데(`-0878`), 사이트맵에 그 시즌 URL 이 아직 없으면
대조가 통째로 빗나가고 상품이 **조용히 조회 대상에서 빠진다.**

그래서 코드가 안 맞으면 `/{성별}/{상품명 슬러그}-4자리` 로 후보를 찾는다.
**후보가 둘 이상이면 고르지 않는다** — 시즌이 다른 두 URL 중 아무거나 집으면
엉뚱한 상품의 재고를 이 상품 것으로 보고하게 된다. 리포트의 "아직 못 받은 상품" 표에
후보를 링크로 띄우니, 사람이 하나를 골라 `data/supplier-urls.json` 에 적어 넣는다.

```json
"arcteryx-beta-jacket-men": { "url": "…/mens/beta-jacket-0868", "via": "manual" }
```

`via:"manual"` 로 적으면 `--fresh` 로 다시 해석해도 지워지지 않는다.

### 상품 추가 — `npm run intake`

```bash
npm run intake -- https://outlet.arcteryx.com/ca/en/shop/mens/sabre-sv-jacket-9910
npm run intake -- <URL> --into="Beta AR Jacket Men's"   # 기존 상품에 색상만 더한다
npm run intake -- <URL> --dry                            # 무엇을 받을지만 본다
```

공식몰 PDP 하나를 상위 프로젝트의 **상품 폴더**로 받아 적는다 —
`스마일리키/아크테릭스/{남성|여성}/{상품}/` 에 색상별 이미지 6~7장과 `가격.txt`.
그 폴더 규칙은 원래 사람이 손으로 채우던 것이고, 임포터(`catalog:import`)가 파일명에서
SKU·색상·뷰를 읽는다. 아울렛처럼 상품이 수시로 들고 나면 손으로는 못 따라간다.

파일명은 **CDN 이 쓰는 이름 그대로**다 — 그 이름이 이미 임포터 규칙과 같다.
다만 **상품코드는 PDP 가 말한 값으로 바로잡는다**: 실측(2026-09-01)에서 아울렛
Alpha SV(X000009989)의 대표 이미지가 정가 상품 X000009899 의 컷을 가리켰다.
그대로 두면 색상은 멀쩡한데 재고가 영영 안 붙는다.

받아 온 뒤:

```bash
cd ..  &&  npm run catalog:import  &&  npm run db:seed -- --commit
```

원산지·소재·취급주의는 여기서 안 건드린다. 그건 `src/details/run.ts` 가 상품 단위로
따로 읽는다(바뀌는 주기가 달라 파이프라인을 나눈다).

#### 가격 — 엑셀이 1순위, `가격.txt` 가 2순위

아크테릭스는 판매가를 「가격표 비교.xlsx」에서 읽는다. 원가·한국 정발가·마진까지
사람이 정해 둔 값이라 **언제나 이긴다.** 행이 없으면 폴더의 `가격.txt` 로 떨어지고,
다른 브랜드가 이미 쓰는 공식(`priceFromCad`)으로 원화가를 잡는다.

```
770CAD                          상품 전체
Stone Red / Dk Stone: 588CAD    색상 하나 — 아울렛은 한 상품 안에서도 값이 갈린다
```

이미 적힌 색상은 다시 받아 와도 덮지 않는다. 손으로 고친 값이 조용히 사라지면 안 된다.

#### 정가몰과 아울렛은 한 브랜드다

`outlet.arcteryx.com` 은 호스트만 다르고 플랫폼은 같다 — 같은 `/ca/en/shop/` 경로에
같은 JSON-LD 를 싣고 robots 도 같은 것을 막는다. 브랜드 판정을 `origin` 접두어로
하면 이 주소가 **어느 브랜드도 아닌 것**이 되어 조회 대상에서 조용히 빠지므로
(실측: 8건이 카탈로그엔 있는데 조회 0건), `brands.ts` 의 `extraHosts` 에 적어 둔다.

같은 이름의 상품이 정가·아울렛으로 따로 팔릴 때는 두 갈래다.

| 원산지가 | 어떻게 |
|---|---|
| 같다 | 한 상품의 색상으로 합친다. 폴더 하나에 두 코드가 섞이고, 색상마다 제 상품코드를 쓴다 |
| 다르다 | 별도 상품으로 둔다 — 폴더명에 `(Outlet)`, 슬러그는 `…-outlet-men`, 화면 이름은 `(아울렛)` |

`originCountry` 는 상품 단위 값이다. 합치면 색상 절반의 원산지가 틀리게 표기되고,
CKFTA(캐나다산 관세 0%)가 걸리면 **세액까지 틀린다** (CLAUDE.md 규칙 5).
실측: 아울렛 Alpha SV 는 CANADA, 정가 Alpha SV 는 CHINA 였다.

### 공식몰 주소 관리 — `재고관리.html`

```bash
npm run manage    # 스마일리키/재고관리.html 생성 → 브라우저로 연다
```

**URL 이 없으면 그 상품 재고는 조용히 빠진다.** 오류가 나지 않으니 알아채기까지 오래
걸린다(캐나다구스 8건이 그럴 뻔했다). 그래서 이 페이지는 **주소 없는 상품을 맨 위에**
둔다. 등록 상품 수 · 수집 페이지 수 · 주소 없음 · 신선도 만료를 함께 센다.

파일(`file://`)로 열리므로 스스로 저장하지 못한다. 대신 고친 칸만 모아
`scripts/official-urls.json` 에 그대로 붙여 넣을 모양의 JSON 을 만들어 준다 —
그 파일이 카탈로그보다 우선하는 원본이기 때문이다. 캐나다구스처럼 색상마다 페이지가
다른 브랜드는 `byColor` 로 나간다.

새 상품을 넣을 때: `catalog:import` → `manage` → 주소 붙여넣기 → `official-urls.json`
저장 → `catalog:import` → `extension` → 크롬에서 확장 새로고침.
자동 수집 브랜드(아크테릭스·코치)는 `npm run intake` 가 폴더와 주소를 한 번에 만든다.

#### 카탈로그의 주소가 해석보다 우선한다

사이트맵·이름 매칭은 추측이고 카탈로그에 적힌 주소는 사람이 확인한 답이다. 캐시를
앞에 두면 예전에 잘못 해석한 URL 이 계속 이긴다. 캐나다구스는 사이트맵이 429 라
이것 말고는 URL 을 알 길이 없다.

색상마다 주소가 있어도 **경로가 같으면 한 페이지로 접는다**(`?Color=` 만 다른 것들).
수집기가 페이지 안에서 색상을 돌기 때문에 한 번이면 충분하다. 반대로 경로가 다르면
전부 남긴다 — 디스크 마감마다 별도 PDP 라 접으면 나머지 재고가 통째로 빠진다.

### 크롬 확장 — 북마클릿을 타이머로

```bash
npm run extension    # data/extension/ 생성 → chrome://extensions 에서 로드
```

북마클릿이 하는 일을 **같은 브라우저 안에서 타이머로** 돌린다. 세션도, 권한 상황도,
읽는 페이지도 북마클릿과 같고 클릭만 없어진다. 기본 주기는 6시간 —
재고 신선도 임계와 같다. 더 자주 돌 이유가 없다.

#### 왜 브라우저 안이어야 하는가

봇 방어를 지나는 것은 코드가 영리해서가 아니라 **사용자의 진짜 브라우저 세션**이기
때문이다. 서버에서 돌리는 자동화는 안 된다 — 실측(2026-08-29)으로 확인했다.

| 시도 | 결과 |
|---|---|
| Playwright 헤드리스 | 차단 |
| Playwright **헤드된 실제 크롬 창**, 새 프로필 | 폴로 첫 요청만 통과 → 두 번째부터 `Access to this page has been denied` |
| 〃 룰루레몬 | 즉시 차단 (218바이트 스텁) |
| 사용자 브라우저(북마클릿·확장) | 통과 |

그래서 자동화는 브라우저 안에서만 성립한다. 대신 **크롬이 켜져 있어야** 돈다.

#### robots.txt 를 브라우저 안에서 읽는다

서버에서는 캐나다구스 robots.txt 가 429 라 읽지 못했다. 브라우저 세션에서는 읽힌다.
그래서 확장은 호스트마다 robots 를 직접 읽어 막힌 경로를 건너뛴다.

**못 읽으면 그 호스트는 건드리지 않는다.** 무엇이 허용됐는지 모르는 채로 두드리지
않는다 (규칙 8). 팝업이 제외 건수를 보여 준다.

#### 안전장치

- 한 번에 여는 탭은 **하나**, 상품 사이 4초 지연, 회차당 상한 80건
- 호스트 권한은 **실제 대상이 있는 오리진만** 적는다. `<all_urls>` 를 요구하지 않는다
- `cookies` · `webRequest` · `history` 권한을 요구하지 않는다 — 로그인·결제 영역은 열지 않는다
- 서비스 워커에서 내려받기가 막히면 결과를 storage 에 남기고 팝업이 저장 버튼을 띄운다.
  **수집을 다 해놓고 결과를 잃는 것**이 가장 나쁘다

#### 확장에는 막힌 브랜드만 넣는다

아크테릭스·코치는 서버에서 그냥 받아진다(`stock:all`). 확장까지 열면 **같은 페이지를
두 번 긁는다** — 회차만 길어지고 사용자 브라우저로 남의 사이트를 괜히 두드리게 된다.
그래서 `automation: 'bookmarklet'` 브랜드만 대상이다. 크롬에 요구하는 사이트 권한도
그만큼 줄어든다(4개 → 2개). 전부 넣으려면 `--all-brands`.

#### 수집이 끝나면 파이프라인이 알아서 돈다

```bash
npm run stock:watch    # 한 번만 켜 두면 된다
```

확장이 수집을 마치면 `ricky-stock-*.json` 이 다운로드 폴더에 떨어진다. 이걸 **신호로**
써서 `stock:all` 을 대신 돌린다 — 북마클릿으로 손수 받은 파일도 똑같이 잡힌다.

확장이 이 명령을 직접 띄울 수는 없다. MV3 확장은 프로세스를 못 띄우고, 띄우려면
네이티브 메시징 호스트를 윈도우에 따로 설치해야 한다. 파일을 신호로 쓰면 그게 필요 없다.

**감시(inotify)가 아니라 폴링이다.** 크롬은 윈도우에서 돌고 다운로드 폴더는
`/mnt/c/...` 인데, WSL2 의 drvfs 는 윈도우 쪽 변경에 inotify 를 올려 주지 않는다 —
`fs.watch` 를 걸면 조용히 아무 일도 안 일어난다. 켜 뒀는데 안 도는 게 제일 나쁜
실패라 처음부터 폴링으로 간다(기본 20초, `--every=`).

받는 중인 파일을 읽으면 JSON 이 잘려 수집분을 통째로 버리므로, **크기가 두 번 연속
같을 때만** 처리한다. 켤 때 이미 있던 파일은 처리한 것으로 친다(안 그러면 켤 때마다
예전 수집분으로 한 번 돈다). 파이프라인이 실패해도 감시는 계속한다.

#### 재부팅을 넘기려면 두 겹이 필요하다

```bash
npm run autostart    # 서비스 파일을 만든다 (켜지는 않는다)
```

WSL 은 재부팅하면 꺼지고, **터미널을 열기 전까지 아예 뜨지 않는다.** 그래서 한 겹으로는
안 된다.

| | 하는 일 | 없으면 |
|---|---|---|
| ① systemd 사용자 서비스 | WSL 안에서 감시를 띄운다 | 터미널에서 매번 직접 켜야 한다 |
| ② 윈도우 작업 스케줄러 | 로그온 때 WSL 자체를 띄운다 | ①을 등록해도 WSL 이 안 떠서 안 돈다 |

②는 `wsl.exe -d <배포판> -- true` 만 부른다. 감시 명령을 직접 부르면 그 프로세스가
로그온 세션에 묶여 같이 죽는다. WSL 만 띄우면 systemd 가 이어서 서비스를 올린다.

**작업 스케줄러가 아니라 시작프로그램 폴더다.** `schtasks /sc onlogon` 은 `/rl highest`
를 빼도 "액세스가 거부되었습니다" 로 막힌다 — onlogon 트리거 자체가 관리자 권한을
요구한다(실측). 시작프로그램 폴더는 사용자 소유라 권한이 필요 없고, `autostart` 가
거기에 `ricky-wsl.vbs` 를 직접 넣는다. `.cmd` 가 아니라 `.vbs` 인 것은 콘솔 창이
번쩍이지 않게 하기 위해서다(`Run ..., 0, False`). 빼려면 그 파일을 지우면 된다.

`loginctl enable-linger` 가 켜져 있어야 터미널을 닫아도 계속 돈다(`autostart` 가 확인해
알려 준다). 로그는 `data/watch.log`.

`systemctl stop` 은 SIGTERM 인데, 이걸 실패로 기록하면 `status` 가 늘 `failed` 로 남아
사람이 볼 때마다 깨진 줄 안다. `SuccessExitStatus=143 SIGTERM` 으로 막았다.

#### 확장이 낡았는지 — 지문 두 개를 본다

| 지문 | 무엇이 바뀌면 달라지나 |
|---|---|
| `catalogFp` | 등록 상품 목록 (북마클릿·확장 공통) |
| `targetsFp` | 확장이 **실제로 열 페이지 목록** |

둘 다 필요하다. 실측 사고: 캐나다구스 URL 을 카탈로그에 채워 확장 대상이 15 → 29페이지가
됐는데 **등록 상품 목록은 그대로**라 `catalogFp` 가 변하지 않았다. 크롬에 옛 확장이 얹힌
채로 캐나다구스 8건이 통째로 빠졌고 아무 경고도 뜨지 않았다. 주소를 새로 채우는 것은
상품을 추가하는 것과 다른 변화이므로 따로 본다.

#### 확장이 못 가는 곳

대상은 `data/supplier-urls.json` 이 해석해 둔 URL 이다. URL 을 아직 모르는 상품은
확장이 갈 곳을 모른다 — 북마클릿으로 **한 번** 받아 두면 `learnUrls` 가 배우고,
그 다음부터 확장이 맡는다. 캐나다구스가 여기 해당한다(사이트맵이 429 라 자동 해석 불가).

### 브랜드마다 손이 가는 정도가 다르다 — 첫 회차만이 아니다

| | 평소 수집 | 사람이 할 일 |
|---|---|---|
| **아크테릭스 · 코치** | `npm run stock:all` | 없음 |
| **폴로 · 룰루레몬 · 캐나다구스 · 투미** | `npm run stock:all` | **매 회차** 북마클릿 — 또는 크롬 확장이 대신 |

**북마클릿은 처음 한 번이 아니라 매번이다.** 첫 수집으로 공식몰 URL 을 학습하긴 하지만,
그 URL 로 자동 수집이 되는 게 아니다 — 사이트가 여전히 막혀 있기 때문이다.
URL 학습이 사 주는 것은 "무엇이 등록됐고 이번에 무엇이 안 들어왔는지"를 리포트가
말할 수 있게 되는 것뿐이다.

그래서 막힌 브랜드는 `automation: 'bookmarklet'` 로 표시하고 **네트워크로 시도조차
하지 않는다.** 표시가 없으면 URL 을 학습한 뒤로 매 회차 차단된 사이트를 헛되이 두드리고,
리포트가 '수집 실패'로 채워져 진짜 실패가 묻힌다.

```
> 아크테릭스 재고 조회 — 대상 24건
  룰루레몬: 자동 수집 불가 — 북마클릿 수집분만 쓴다
> 코치 재고 조회 — 대상 9건
  캐나다구스: 자동 수집 불가 — 북마클릿 수집분만 쓴다
  폴로 랄프로렌: 자동 수집 불가 — 북마클릿 수집분만 쓴다
```

**재고는 6시간이면 낡는다**(PROJECT.md §6). 주문매입 상품은 그 안에 확인된 재고만
결제를 연다. 북마클릿 브랜드는 팔려면 그 주기로 사람이 한 번 눌러야 한다는 뜻이다.
캐나다구스는 디스크마다 PDP 가 따로라 디스크별로 눌러야 하고,
카테고리 목록에서 **목록수집**을 쓰면 한 번에 걸린다.

### 북마클릿은 카탈로그가 바뀌면 다시 설치해야 한다

북마클릿은 등록 상품 목록(코드·이름·슬러그)을 **안에 박아** 배포한다.
브라우저 북마크는 그 시점의 사본이라, 상품을 추가해도 알아서 갱신되지 않는다.
안 하면 새 상품이 목록수집에서 **조용히** 빠진다.

다시 설치해야 하는 때는 둘뿐이다.

| | |
|---|---|
| 카탈로그가 바뀐 뒤 (`npm run catalog:import`) | 새 상품이 목록에 없다 |
| 수집기 코드를 고친 뒤 | 고친 규칙이 반영되지 않는다 |

평소 수집만 할 때는 다시 설치할 필요 없다.

기억에 맡기지 않는다 — 북마클릿에 **카탈로그 지문**을 심어 두고 캡처마다 실어 보낸다.
`stock` 이 지금 카탈로그와 대조해 어긋나면 말해 준다.

```
! 북마클릿이 낡았다 — 심겨 있는 등록 상품 목록이 지금 카탈로그와 다르다.
  새로 등록한 상품은 목록수집에서 조용히 빠진다.
  npm run bookmarklet 으로 다시 설치해라 (두 버튼 다시 드래그).
```

지문이 아예 없는 캡처도 낡은 것으로 본다 — 지문 기능보다 오래된 북마클릿이라는 뜻이다.

### 카탈로그에 등록된 상품만 — 이게 기본값이다

자동 수집도 목록수집도 **상위 프로젝트 카탈로그에 등록된 상품만** 본다.
탐색이 필요하면 `--no-catalog` 로만 사이트맵을 훑는다.

예전엔 반대였다. `npm run stock:all` 이 브랜드별 사이트맵에서 최신 25건씩 긁어 와,
리포트가 Cerium Jacket · Proton Heavyweight Hoody 처럼 **등록하지도 않은 상품**으로
채워지고 정작 등록 상품 24건은 조회되지 않았다(실측 2026-08-29).
우리가 파는 건 카탈로그에 있는 것뿐이므로 그게 기본이어야 한다.

조회할 URL 목록이 **비어 있어도 사이트맵 탐색으로 물러나지 않는다.**
"조회할 게 없다"는 "아무거나 긁어 와라"가 아니다.

#### 코드가 없는 브랜드는 이름으로 거른다

룰루레몬은 상품코드 체계가 없다. 예전엔 그래서 필터가 통째로 꺼졌고,
목록 전체(실측 81건)를 8분에 걸쳐 받아 놓고 정작 쓸 건 4건이었다.
룰루레몬 URL 은 상품명이 그대로 슬러그라 이름으로 거를 수 있다.

```
/en-ca/p/equipment/Womens-Fast-and-Free-Trail-Running-Vest/_/prod11890062
```

슬러그는 **앞뒤 경계를 맞춰** 찾는다. 안 그러면
`mens-fast-and-free-trail-running-vest` 가 `wo|mens-fast-…` 안에서 걸려
남성 상품이 여성 URL 에 붙는다 — 룰루레몬은 남녀 이름이 똑같다.

카탈로그가 남녀 조끼를 **같은 이름**으로 들고 있어(성별은 별도 필드) 슬러그도 같다.
그래서 일치한 첫 건에서 멈추지 않고 전부 표시한다 — 멈추면 나머지 하나가
수집됐는데도 늘 "못 찾음" 으로 보고된다.

이름이 사이트와 조금만 달라도 0건이 될 수 있다. 그럴 때는 막다른 길로 두지 않고
"목록 전체를 받아 둘까요?" 를 묻는다.

등록이 안 된 상품은 목록 페이지에 링크가 보여도 걸러진다 — 그래서 알림이 등록된
상품명을 성별과 함께 보여 준다. "찾는 상품이 이 목록에 없으면 카탈로그에 등록되지
않은 것"이다.

원본 폴더가 규칙을 벗어나면 임포터가 상품을 통째로 건너뛴다. 이제 이유를 찍는다.

| 원본 상태 | 결과 |
|---|---|
| 색상 폴더 없이 이미지가 상품 폴더에 바로 있음 | **카탈로그에 안 생김** — 색상명 폴더를 만들어 옮겨라 |
| `details.txt` 없음 / 가격(`218CAD`) 없음 | **카탈로그에 안 생김** |
| `details.txt` 에 `Style Number` 없음 | 카탈로그엔 생기지만 **재고 조회 대상에서 빠짐** (SKU 가 `POLO-…` 가 된다) |

### Supabase 적재 — `data/연동-*.json`

카탈로그 모드로 돌리면 상위 프로젝트가 Supabase 에 넣을 산출물이 함께 떨어진다.
`src/stock/link.ts` 가 재고 행을 카탈로그 variant 에 붙이고,
`src/stock/supabase.ts` 가 그 결과를 적재 모양으로 낸다.

```json
{
  "slug": "polo-cable-knit-cotton-cardigan-men",
  "sku":  "100066198-CAMEL-MELANGE",     // Supabase variants 조인 키
  "color": "Camel Melange",
  "catalogCadCents": 22800,              // 카탈로그를 만들 때 쓴 원가
  "observedCadCents": 22800,             // 이번에 관측한 원가
  "priceChanged": false,
  "onSale": false,
  "sizes": [{ "label": "M", "availability": "in_stock", "cadCents": 22800 }],
  "checkedAt": "2026-08-29T17:49:43.118Z",
  "source": "manual"
}
```

**이 파일은 관리자 전용이다.** CAD 원가가 들어 있다 — CLAUDE.md 규칙 1에 따라
고객용 API 응답에 실으면 안 된다. `meta.audience: "admin"` 을 박아 둔 이유다.

#### 가격의 단위는 색상이다

실측(2026-08-29, 380행): 같은 색상 안에서 사이즈별로 가격이 갈리는 경우는 **0건**.
색상별로는 갈린다 — 랄프로렌 650001 은 Fawn Grey Heather · Polo Black 이 CA$188.50,
나머지가 CA$198.00. 카탈로그 variant 도 (상품, 색상) 단위라 결이 맞는다.

사이즈별로 갈리는 날이 오면 **최저가가 아니라 가장 흔한 값**을 쓴다.
최저가를 쓰면 못 사는 사이즈의 가격으로 판매가를 매기게 된다.

#### 신선도는 여기서 판정하지 않는다

`checkedAt` 만 싣는다. `ageHours` 나 `stale` 을 계산해 넣으면 파일이 만들어진 순간의
값이 굳어 버리고 받는 쪽이 그 굳은 값을 믿는다.
신선도 게이트(기본 6h, PROJECT.md §6)는 **요청 시점에** 계산해야 하는 것이다.

#### 세일이라고 말하지 않은 마크다운은 알리기만 한다

랄프로렌은 색상별로 값을 내려도 JSON-LD 에 세일 표기를 남기지 않는다.
그 값을 그대로 원가로 넣으면 마크다운이 끝났을 때 원화 판매가가 조용히 어긋난다.
그렇다고 "제일 비싼 색이 정가"라고 추론하면 없는 세일을 지어낸다(실측 사고: 코치 43%).
그래서 **판정하지 않고 `priceAlerts` 로 알린다.**

```
! polo-cable-knit-cotton-polo-sweater-men: 색상별 가격이 갈리는데 세일 표기가 없다
  (보통 CA$198.00, Fawn Grey Heather CA$188.50, Polo Black CA$188.50)
```

카탈로그에 등록되지 않은 색상은 알림에 넣지 않는다 — 안 파는 색의 가격은 판매가와 무관하다.

#### SKU 오타는 조인을 통째로 끊는다

SKU 는 Supabase 조인 키다. 원본 폴더명에 오타가 있으면 그게 SKU 에 굳는다 —
실측: `Collection Camel Melang` 폴더 탓에 SKU 가 `…-COLLECTION-CAMEL-MELANG` 이 되어
수집한 `Collection Camel Melange` 와 대조되지 않았다.
그래서 폴로·룰루레몬은 `FOLDER_FIX` 로 **바로잡은 이름**으로 SKU 를 만든다.
코치는 폴더명이 `소재,하드웨어,색상` 이라 원본 그대로 둔다 — 바꾸면 소재가 다른 같은 색이
같은 SKU 로 뭉개진다.

### 실패는 품절이 아니다

차단·마크업 변경으로 수집이 실패하면 `error` 로 분리해 보고하고, variant 를 0개로 두지 않는다.
실패를 품절로 읽으면 멀쩡한 상품이 판매 중지되고, 마지막 성공값으로 계속 팔면
주문 후 매입 실패로 이어진다 (PROJECT.md §6.3 5번).

## 사용

```bash
npm run doctor                       # ① 엔드포인트 생존 확인 — 항상 먼저
npm run stock  -- --watch            # 재고 조회 (색상 × 사이즈) ← 위 절 참조
npm run bookmarklet                  # 차단 브랜드용 반자동 수집 북마클릿
npm run extension                    # 크롬 확장 생성 (막힌 브랜드를 타이머로)
npm run stock:watch                  # 수집 파일이 떨어지면 stock:all 자동 실행
npm run manage                       # 재고관리.html — 공식몰 주소 넣는 곳
npm run autostart                    # 위 감시를 재부팅 후에도 자동으로 켜지게 등록
npm run signals -- --brand=coach     # 한국 인기도 신호만
npm run catalog -- --brand=tommy --new   # 캐나다 카탈로그만
npm run scan    -- --limit=40        # 전체 → data/ 에 리포트 생성
```

| 옵션 | 뜻 |
|---|---|
| `--brand=<key[,key]>` | `arcteryx tommy polo canadagoose lululemon coach tumi`. 기본 전체 |
| `--limit=<n>` | 브랜드당 수집 상품 수 (기본 25) |
| `--new` | 최근 120일 내 신제품만 |
| `--fresh` | 캐시 무시 |
| `--no-signals` | 네이버 인기도 신호 생략 |
| `--no-kr` | 한국 가격 수집 생략 |
| `--watch[=파일]` | 재고 조회 대상을 URL 목록으로 지정 (기본 `watchlist.txt`) |
| `--import[=디렉터리]` | 북마클릿 수집 파일을 읽는다 (기본 다운로드 폴더) |
| `--all` | 자동 + 북마클릿을 한 번에 돌려 리포트 하나로 합친다 (`npm run stock:all`) |
| `--all-brands` | 확장에 자동 수집 브랜드까지 넣는다 (`npm run extension`, 기본은 막힌 브랜드만) |
| `--every=<초>` | `stock:watch` 폴링 간격 (기본 20) |
| `--no-catalog` | 카탈로그를 무시하고 사이트맵에서 훑는다 (`npm run stock:scan`). **기본은 등록 상품만** |

산출물은 `data/` 에 세 벌로 떨어진다 — 사람이 읽는 `.md`, 엑셀용 `.csv`, 재처리용 `.json`.

## 브랜드별 접근 현황 (2026-08-26 실측)

`doctor` 가 매번 다시 재는 값이다. 사이트 방어 정책은 수시로 바뀐다.

| 브랜드 | CA 자동수집 | 재고 조회 | KR 수집 | 가격 비교 |
|---|---|---|---|---|
| **코치** | ✅ HTTP · 1,748건 | ✅ 자동 | ✅ HTTP · 559건 | ✅ **정확 매칭 230건** |
| **아크테릭스** | ✅ 브라우저 · 462건 | ✅ 자동 | ❌ SPA | CA 단독 |
| **타미힐피거** | ✅ HTTP · 8,901건 | ⚠️ 미검증 | ❌ 해외 IP 차단 | CA 단독 |
| **폴로** | ❌ PerimeterX | 🔖 북마클릿 | ✅ HTTP · 4,531건 | KR 단독 |
| **룰루레몬** | ❌ Akamai | 🔖 북마클릿 | ❌ Akamai | 불가 |
| **캐나다구스** | ❌ Kasada (앞문까지) | 🔖 북마클릿 | ❌ SPA | 불가 |
| **투미** | ❌ 연결 차단 | 🔖 북마클릿 | ⚠️ 사이트맵 없음 | 불가 |

🔖 = 자동 수집은 막혔지만 북마클릿(반자동)으로 수집 가능

#### 같은 Kasada 인데 아크테릭스는 되고 캐나다구스는 안 되는 이유

방어의 종류가 아니라 **어디에 걸었느냐**가 다르다 (2026-08-29 실측).

| | 아크테릭스 | 캐나다구스 |
|---|---|---|
| `robots.txt` | HTTP ok | **429** (3회 재시도 전부 실패) |
| `sitemap.xml` | HTTP ok · index 2 | **429** |
| 진입 페이지 | HTTP ok | **차단(Kasada)** — 브라우저로도 챌린지 |
| 상품 상세 | Kasada → 브라우저로 통과 | 도달 불가 |

아크테릭스는 Kasada 를 **PDP 에만** 걸어 두고 사이트맵·robots 는 정적 파일로 내준다.
그래서 목록은 HTTP 로 확보하고 PDP 만 브라우저로 연다.
캐나다구스는 앞문부터 막혀 있어 뚫을 문이 하나도 없다.

`robots.txt` 를 못 읽으면 **거기서 멈춘다.** 무엇이 허용됐는지 모르는 채로 계속
두드리는 건 하지 않는다 (CLAUDE.md 규칙 8). 그래서 북마클릿으로 간다 —
사용자 브라우저는 이미 정상적으로 사이트를 보고 있는 세션이다.

아크테릭스도 무제한은 아니다. `--fresh` 로 연속 요청하면 429 가 난다(실측).
캐시와 요청 간 지연 덕에 평소에 안 걸리는 것뿐이다.

수치는 2026-08-26 실측이다. `npm run doctor` 가 매번 다시 잰다.
차단 페이지는 HTTP 200 으로 오기 때문에 내용까지 검사해 판정한다 —
"바이트가 왔다"를 성공으로 세면 진단이 통째로 거짓이 된다.

**코치가 가장 신뢰도가 높다.** CA와 KR이 같은 상품 코드(`CAM16.html`)를 쓰기 때문에
이름을 맞혀 추측할 필요 없이 ID로 바로 대조된다. 랄프로렌·투미도 같은 구조지만
CA 쪽 수집을 뚫어야 한다.

## 설계 판단

**왜 커뮤니티를 직접 긁지 않는가**
더쿠·디시·클리앙 직접 크롤링은 약관상 회색지대이고 노이즈가 크다. 네이버 검색 API의
블로그·카페 문서 수는 공식·무료·합법이면서 국내 언급량의 대리 지표로 충분히 기능한다.

**왜 브랜드별 CSS 셀렉터를 7벌 만들지 않는가**
7개 브랜드는 서로 다른 커머스 플랫폼 위에 있지만 SEO 때문에 대부분 schema.org
`Product`/`ProductGroup`을 심는다. 셀렉터는 분기마다 깨지지만 이 마크업은 SEO 자산이라
잘 바뀌지 않는다. 그래서 JSON-LD를 1순위로 두고 실패한 브랜드만 개별 처리한다.

**왜 카테고리 페이지 대신 사이트맵인가**
무한 스크롤을 긁는 것보다 상대 서버에 훨씬 가볍고, `lastmod`라는 신제품 신호를 덤으로 준다.
정렬 전에 잘라내지 않는다 — 그러면 "신제품"이 카탈로그 앞부분의 최신일 뿐이게 된다.

**인기도를 언급량만으로 재지 않는 이유**
"최근 1~2년 인기"를 물었으므로 총량만 보면 오래된 스테디셀러가 이긴다.
언급량 30% + 검색 증가세 30% + 최신성 20% + 유통폭 20%로 나눠 신규 부상을 잡아낸다.

**정가와 세일가를 반드시 분리한다**
코치는 `ProductGroup.offers`에 정가(CA$360)를, variant에 세일가(CA$180)를 싣는다.
최저가만 보면 "48% 싸다"가 사실은 특정 컬러웨이 세일이라는 걸 놓친다. 매입 판단이
달라지므로 리포트에 정가를 함께 적는다.

## 프로젝트 규칙과의 연결

- **통합 단일가** — 리포트의 원가(CAD)·마진·환율은 운영 내부 데이터다. 스토어에 노출하지 않는다 (CLAUDE.md 규칙 1)
- **정수 금액** — KRW는 원 단위 정수, CAD는 cent 단위 정수. 파싱 단계에서 float을 만들지 않는다 (규칙 2)
- **판매가 산출** — 앱의 `src/lib/pricing` 을 그대로 재사용한다. 계산 로직을 두 곳에 두지 않는다 (PROJECT.md §5)
- **원산지** — `originCountryHint` 는 페이지 텍스트에서 긁은 참고값이다.
  CKFTA 판정은 실물 라벨 확인 후에만 한다 (규칙 5)
- **정중한 크롤링** — robots.txt 준수, 호스트별 지연 2.5초·동시성 2, 429는 15초부터 지수 백오프.
  랄프로렌은 robots가 `*/search*`를 막으므로 검색 경로를 쓰지 않는다 (규칙 8)
- **한글 경로** — Node 스크립트는 `new URL().pathname` 대신 `fileURLToPath` 를 쓴다

## 구조

```
src/
  config/brands.ts     브랜드 레지스트리 — 엔드포인트·URL 패턴을 여기 한 곳에 모은다
  core/                politeness(robots·지연·백오프) · fetcher · browser · cache
  extract/             jsonld · sitemap · price · blockpage   ← 사이트 무관 순수 추출기
  adapters/generic.ts  사이트맵 + JSON-LD 범용 어댑터 (7개 브랜드 중 6개 커버)
  signals/             네이버 API 클라이언트 + 인기도 점수(순수 함수)
  match/               상품명 정규화 · CA↔KR 매칭(순수 함수)
  stock/               재고 조회 — 카탈로그 대조 · 사이즈·색상 정규화 · 변화 감지 · html/md/csv 리포트
  report/              markdown · csv
  pipeline.ts          오케스트레이션
```

계산·정규화·점수·차단판별·재고대조는 전부 순수 함수로 두고 단위 테스트를 붙였다 (`npm test`, 203개).

## 알려진 한계

**4개 브랜드는 봇 차단으로 자동 수집이 불가능하다** (룰루레몬·캐나다구스·투미, 폴로 CA).
→ **북마클릿(반자동)으로 수집한다.** 위 "차단 브랜드는 반자동으로" 절 참조.

실측 기록 (2026-08-28):

- **헤드리스 여부는 무관하다.** WSLg 로 실제 창을 띄운 브라우저(`headless:false`)로도
  폴로·캐나다구스는 결과가 동일했다(각각 PerimeterX 캡차 9.7KB, Kasada 748바이트).
- **룰루레몬은 첫 요청만 통과한다.** 사이트맵 200건 확보 후 PDP 1건은 색상·사이즈·재고까지
  정상 수집됐으나, 이후 요청부터 본문 218바이트 껍데기만 돌아온다.
  12초 간격으로 늦춰도 동일했다 — 속도가 아니라 세션/IP 단위 잠금이다.
- **투미는 연결 자체가 안 된다** (HTTP·브라우저 모두 타임아웃).

자동화를 계속 밀 경우의 선택지:

1. **브랜드 제휴/어필리에이트 피드** — 룰루레몬·랄프로렌은 Rakuten Advertising 에서
   상품 피드를 제공한다. 다만 갱신이 하루 1회라 §6.5 6시간 게이트에 미달하고,
   어필리에이트 약관이 자사 커머스 목적 사용을 제한하는 경우가 많다. 신청 전 조항 확인 필수.
2. **상용 언블로킹 프록시** — Bright Data Web Unlocker 기준 $1.50/1K.
   3개 브랜드 60 SKU 를 §6.4 주기로 돌리면 월 25,650회 ≈ $38. 200 SKU 면 약 $130.
   단 사이트 약관 위반이다.

그 밖에:

- **국내 최저가 축이 없다.** 네이버 쇼핑 검색 API 종료(2026-07-31) 이후
  가격을 주는 공개 API 가 없다. 대체 소스가 생기면 `lookupKrLowest()` 하나만 채우면 된다.
- **이름 유사도 매칭(신뢰도 1.0 미만)은 사람이 확인해야 한다.** 색상·시즌 차이를 구분하지 못한다.
- 재고는 리포트 생성 시점 값이다. 실제 판매 개시 전에는 §6.5 신선도 게이트(6시간)를 통과해야 한다.
