# RICKY 소싱 리서치 파이프라인

한국 인기도 신호 × 캐나다 공식몰 신제품 × CA/KR 가격 비교를 자동화한다.
PROJECT.md §6(공급처 모니터링)의 **상류 단계** — 이미 등록한 SKU를 감시하는 게 아니라,
**무엇을 팔지 발굴**하는 단계다.

```
[1] 한국 인기도 신호      네이버 블로그·카페 언급량 + 검색어 트렌드 (API HUB)
        ↓
[2] 캐나다 공식몰 카탈로그  사이트맵(lastmod) → 신제품 판정 → JSON-LD로 가격·재고·variant
        ↓
[3] 매칭                  상품코드 정확 매칭 → 실패 시 한/영 토큰 유사도
        ↓
[4] 한국 가격             브랜드 한국 공식몰 정가
        ↓
[5] 리포트                마진 산출 → 소싱 우선순위 (Markdown + CSV + JSON)
```

---

## 준비

```bash
cd 스크래핑
npm install
npm run browsers                   # Playwright Chromium

# WSL/리눅스는 시스템 라이브러리가 추가로 필요하다 (1회, sudo)
sudo npx playwright install-deps chromium
#  또는: sudo apt-get install -y libnss3 libnspr4 libasound2t64

cp .env.example .env               # 네이버 API 키 입력
```

### 네이버 API 키 — 2026년 이관 주의

네이버가 검색·데이터랩 API 를 개발자센터에서 **NAVER API HUB(네이버 클라우드)** 로 옮겼다.
그래서 developers.naver.com 애플리케이션 등록 화면의 "사용 API" 드롭다운에는
**검색·데이터랩이 나오지 않는다.** 목록에 없는 게 정상이며, 신규 발급은 HUB 에서 받는다.

| API | 상태 |
|---|---|
| 블로그·카페글·뉴스 검색 | API HUB 로 이관 |
| 검색어 트렌드(데이터랩) | API HUB 로 이관 |
| **쇼핑 검색** | **2026-07-31 종료 · 공식 대체 없음** |

- 신규 발급: https://www.ncloud.com/product/applicationService/naverApiHub
  → `.env` 의 `NAVER_HUB_KEY_ID` / `NAVER_HUB_KEY`
- 기존 developers.naver.com 키가 있으면 **2027-06-30 까지** 그대로 쓸 수 있다
  → `.env` 의 `NAVER_CLIENT_ID` / `NAVER_CLIENT_SECRET`

둘 중 무엇이 설정됐는지는 코드가 자동 판별해 도메인과 인증 헤더를 바꾼다.
`npm run doctor` 가 실제로 한 번 호출해 키가 통하는지까지 확인한다.

**쇼핑 검색 종료의 영향** — 국내 "최저가" 축이 사라졌다. 국내 가격 비교는
브랜드 한국 공식몰 정가만 쓴다. 인기도 점수는 유통폭(commerce) 축을 빼고
남은 가중치를 재정규화하므로, 축이 없다고 점수가 깎이지는 않는다.

## 재고 조회 (색상 × 사이즈)

캐나다 공식몰의 **variant 단위** 재고를 조회한다 (PROJECT.md §6).
상품 하나가 아니라 색상 × 사이즈 조합 하나하나가 수집 단위다 — 실제 매입이 일어나는 단위이기 때문이다.

```bash
npm run stock:catalog   # ← 평소엔 이것만. 상위 프로젝트에 등록된 상품만 조회
```

**조회 대상은 상위 프로젝트 카탈로그다** (`src/lib/catalog.generated.ts`).
감시 목록을 손으로 관리하면 반드시 카탈로그와 어긋난다 — 상품을 등록해도 조회에 안 들어가고,
뺐는데 계속 조회한다. 등록된 상품이 곧 조회 대상이 되게 했다.

연결 고리는 **SKU 접두어에 들어 있는 브랜드 상품코드**다.

| 브랜드 | 카탈로그 SKU | 상품코드 | 공식몰 URL 에서 |
|---|---|---|---|
| 아크테릭스 | `X000010932-GRAPHITE-BLACK` | `X000010932` | 뒤 4자리 `…-0932` |
| 폴로 | `100066198-CAMEL-MELANGE` | `100066198` | `/100066198.html` |
| 코치 | `CDZ42-BRASS-MAPLE` | `CDZ42` | `/CDZ42.html` |
| 룰루레몬 | `LULULEMON-FLAMINGO-FUN` | 없음 | 이름으로만 대조 |

사이트맵을 브랜드당 한 번 읽어 URL 을 찾고 `data/supplier-urls.json` 에 남긴다.
매 실행마다 4만 건짜리 XML 을 다시 받을 이유가 없다.
북마클릿으로 받은 상품의 URL 도 여기 학습된다 — 사이트맵이 막힌 브랜드는 이게 유일한 출처다.

실측: 카탈로그 48건 중 35건 수집(아크테릭스 24 · 코치 8 · 폴로 3), URL 해석 31건 + 북마클릿 학습 4건.

목록수집이 주변 상품까지 담아 와도 **등록된 상품만 남기고** 나머지는 버린다.
그리고 아직 못 받은 상품을 리포트 상단에 띄운다 — 다음에 무엇을 할지 그게 정해 준다.

카탈로그를 무시하고 감시 목록으로 돌리려면:

```bash
npm run stock:all      # watchlist.txt + 북마클릿 수집분
```

`data/index.html` 이 **고정 주소 대시보드**다. 즐겨찾기에 걸어 두면 항상 최신 리포트로
들어갈 수 있고 지난 이력도 한 표에서 훑을 수 있다. 실행할 때마다 갱신된다.

개별로 돌릴 수도 있다.

```bash
cp watchlist.example.txt watchlist.txt   # 감시할 상품 URL 을 적는다
npm run stock -- --watch                 # 자동 수집만 (아크테릭스·코치)
npm run stock -- --import                # 북마클릿 수집분만 (폴로·룰루레몬·캐나다구스)
npm run stock -- --brand=arcteryx --limit=10   # 카탈로그 최신순 N개
```

산출물은 `data/재고-{타임스탬프}.{html,md,csv,json}` 네 벌 + 고정 주소 `data/index.html` 이다.
실행할 때마다 **직전 스냅샷과 대조해 변화를 뽑는다.**

**HTML 리포트가 기본 보기다.** 실행하면 브라우저에서 열 경로가 출력된다
(WSL 이면 `\\wsl.localhost\...` 형태). 마크다운은 매트릭스가 커지면 읽기 어렵고
필터가 없어서, 상품이 몇 개만 넘어가도 HTML 쪽이 훨씬 낫다.

- 브랜드 칩 · 검색(상품명·코드·색상) · "품절 있는 상품만" 필터
- 색상 × 사이즈 격자, 칸에 마우스를 올리면 SKU·가격
- 변화(품절·재입고·가격변동)를 유형별 색으로 상단에 배치
- 상품 카드 접기/펼치기, 다크 모드 자동
- 외부 의존 없는 파일 하나 — `file://` 로 바로 열린다

```
| 유형      | 상품                    | 색상   | 사이즈 | 변화                          |
| 품절      | Proton Heavyweight Hoody | Azalea | S     | in_stock → out_of_stock       |
| 재입고    | Beta Jacket Men's       | Black  | XS    | out_of_stock → in_stock       |
| 가격 인상 | Denim Hooded Zip Jacket | Khaki  | XXL   | CA$120.00 → CA$167.50 (+47.50)|
```

마크다운 리포트는 색상 × 사이즈 격자로 그린다 (● 재고 · ◐ 임박 · ○ 품절 · · 미편성).

```
| 색상 \ 사이즈 | XS | S | M | L | XL | XXL | XXXL |
| Black         | ●  | ● | ● | ● | ●  | ●   | ●    |
| Sea Salt      | ●  | ● | ○ | ● | ●  | ●   | ●    |
```

### 차단 브랜드는 반자동으로 — 북마클릿

룰루레몬·캐나다구스·폴로는 봇 차단으로 자동 수집이 안 된다(아래 실측 참조).
자동화로 뚫는 대신 **운영자가 평소 쓰는 브라우저로 보고 있는 페이지**에서 데이터를 걷어 온다.
진짜 사람이 진짜 브라우저로 보는 것이므로 탐지가 성립하지 않고 약관 문제도 없다.

**북마클릿이란** — 주소 대신 코드가 든 즐겨찾기다. 보통 북마크는 클릭하면 그 사이트로
이동하지만, 북마클릿은 **지금 보고 있는 페이지에서** 코드가 실행된다. 페이지 이동은 없다.

```bash
npm run bookmarklet          # 설치 페이지 생성 (한 번만)
```

출력된 경로의 HTML 을 크롬에서 열고, **두 버튼을 북마크바로 끌어다 놓는다**
(북마크바가 안 보이면 `Ctrl+Shift+B`).

| | 목록수집 | 재고수집 |
|---|---|---|
| **어디서** | 카테고리 · 검색결과 · 위시리스트 | 상품 상세 페이지 |
| **한 번에** | 그 목록에서 **카탈로그 등록 상품만** | 상품 1건 |
| **시간** | 상품당 약 7초 (34건이면 5분) | 즉시 |
| **쓰는 때** | **평소 점검.** 눌러 두고 기다리면 된다 | 매입 직전 한 상품을 정확히 |

상품마다 북마크를 누르게 하면 하루 30번을 눌러야 하고, 그러면 결국 안 쓰게 된다.
그래서 목록수집이 기본이고, **브랜드당 한 번이면 된다.**

`npm run bookmarklet` 이 카탈로그 상품코드를 북마클릿에 심는다. 전체보기 목록에서
누르면 수백 건 중 **등록된 상품만 골라 담는다** — 실측(코치 여성 전체보기):
상품 링크 34건 중 카탈로그 상품 5건만 수집했다. 다 받아 봐야 대조 단계에서 버려진다.

목록을 끝까지 스크롤해야 한다. 화면에 뜬 상품만 HTML 에 있기 때문이다.
카탈로그가 바뀌면 `npm run bookmarklet` 을 다시 돌려 북마클릿을 갱신한다. 카테고리 페이지에서 한 번 누르면 상품을 하나씩
**같은 출처 iframe 으로 띄워 실제 렌더링한 뒤** 읽는다 — fetch 로 HTML 만 받으면
화면 상태(품절 버튼)를 알 수 없기 때문이다.

수집이 끝나면 파일 하나가 저장된다. 마지막에 한 번만:

```bash
npm run stock:all                         # 자동 수집분과 함께 리포트 하나로
npm run stock -- --import=/경로            # 북마클릿 수집분만
```

> 실측(코치 카테고리): 상품 50건을 찾아 34건으로 정리한 뒤 912 variant 를 수집했다.
> 앵커 태그로는 0건이었다 — 요즘 목록 페이지는 JS 로 그리므로 HTML 본문까지 훑는다.
> 다국어 사이트는 같은 상품의 `/fr/` 판과 언어 접두어 없는 판이 섞여 중복이 나므로
> 현재 페이지 언어와 다른 URL 은 버린다.

> 북마클릿은 JSON-LD **원문**과 **화면에서 읽은 사이즈 상태**를 담아 온다.
> 해석은 `--import` 쪽 추출기가 한다 — 수집 경로가 둘이어도 해석은 한 곳에서만 해야 갈라지지 않는다.

#### 색상이 6개를 넘으면 사이즈가 사라진다 (랄프로렌)

실측한 규칙이다.

| 색상 수 | JSON-LD 사이즈 |
|---|---|
| **≤ 5** | 모든 색상에 있음 (100066198: 3색 → 정상) |
| **≥ 6** | **하나도 없음** (625239: 11색 → 색상 정보만) |

그래서 같은 브랜드인데 어떤 상품은 매트릭스가 다 차고 어떤 상품은 한 색만 찬다.
6색 이상인 상품은 목록수집이 iframe 안에서 색상을 눌러 가며 읽는다.

**색상 클릭이 다른 상품으로 이동하면 즉시 멈춘다.** 코치는 색상 클릭이
`reagan-penny-loafer/CAP31` → `reagan-loafer/CCN27-CBD` 로 넘어간다.
그대로 읽으면 다른 상품의 사이즈를 이 색상 것으로 기록하게 된다 — 없는 재고를 만드는 셈이다.

이 순회는 **iframe 안에서만** 한다. 사용자가 보고 있는 탭에서 클릭하면 페이지가 넘어가
수집이 통째로 날아간다. 그래서 단건 수집(재고수집)은 색상을 돌지 않는다 —
색상은 사람이 고르고 누르는 게 맞다(여러 번 눌러도 합쳐진다).

#### JSON-LD 를 못 믿는 사이트가 있다

두 소스가 서로 다른 방식으로 불완전해서, 덮어쓰지 않고 **합집합**으로 병합한다.

| 사이트 | JSON-LD | 화면 |
|---|---|---|
| **랄프로렌** | 사이즈를 일부만 실음 (한 색상에 S·M 둘만), 재고는 전부 `InStock` | 전 사이즈 + 실제 품절 상태 |
| **코치** | 6사이즈 전부 + 정확한 품절 상태 | 살 수 있는 버튼만 그림 (품절은 아예 안 보임) |

- 화면에 있는 사이즈 → **화면의 재고 상태가 이긴다** (실제로 보이는 것이므로)
- JSON-LD 에만 있는 사이즈 → **그대로 둔다** (화면에 없다고 없는 게 아니다)
- 선택되지 않은 색상 → **건드리지 않는다** (화면에 안 떠 있으니 알 수 없다)

리포트는 이 셋을 구분해 그린다.

| 기호 | 뜻 |
|---|---|
| `●` `○` | 재고 있음 / 품절 — 확인된 값 |
| `·` | 미편성 — 그 색상에 그 사이즈가 애초에 없다 |
| `?` | **미확인** — 사이즈 정보를 못 받았다. 재고가 없다는 뜻이 아니다 |

`?` 를 `·` 로 그리면 재고가 멀쩡한 색상이 "살 수 없음"으로 보인다.

**모르는 것은 재고로 세지 않는다.** 랄프로렌은 사이즈를 안 실어 준 색상 전용 행에도
`InStock` 을 적어 보낸다. 그대로 세면 사이즈를 하나도 못 받은 상품이 `재고 24/24` 로
찍힌다(실측 사고: 638616, 16색 중 1색만 사이즈가 옴). 그래서 헤더 숫자는 **확인된
variant 만** 세고, 나머지는 `미확인 15색` 배지로 따로 보여 준다.

#### 수량 드롭다운의 "1" 은 사이즈가 아니다

랄프로렌 페이지의 수량 선택이 사이즈처럼 생겨서 매트릭스에 `1` 열이 생긴 적이 있다.
북마클릿과 import 양쪽에 같은 사이즈 토큰 규칙을 둔다 — 북마클릿을 고쳐도
**사용자가 재설치하기 전에 만든 캡처가 계속 들어오기** 때문이다.
숫자 사이즈는 신발 치수 범위(5~15)로 좁힌다.

### 사이즈를 어디서 읽는가

브랜드마다 사이즈가 든 자리가 다르다. `src/stock/normalize.ts` 가 이 차이를 흡수한다.

| 대상 | size 필드 | 실제 사이즈 |
|---|---|---|
| Arc'teryx 전 품목 | `"XS"` … `"XXXL"` | size 필드가 정본 |
| Coach 의류 | `"M"` | size 필드 = SKU 토큰 |
| **Coach 신발** | `"extra wide"` (폭 라벨) | **SKU 안에만** — `CCN27 CBD  9.5 D` → `9.5 D` |
| Coach 가방·지갑 | `"large wristlet"` (분류 라벨) | 사이즈 개념 없음 → `-` |

Coach 신발에서 size 필드만 믿으면 9.5 와 10 이 똑같이 "extra wide" 로 뭉개져
사이즈별 재고 조회가 성립하지 않는다. 그래서 SKU 를 파싱해 치수와 폭을 되찾는다.

### 같은 색상·사이즈가 둘 이상일 때

Coach 는 스타일코드가 다른 관련 상품을 한 페이지에 묶어 둔다.
Reagan Penny Loafer 페이지에는 `CAP31` / `CCN27` / `CW699` 세 스타일이 들어 있고,
`CAP31`의 "Black 7 D"와 `CW699`의 "Black 7 D"는 **재고가 서로 다르다.**
그래서 (색상, 사이즈)가 겹치면 스타일코드로 먼저 갈라 매트릭스를 여러 개 그린다.
하나로 뭉개면 한 쪽이 조용히 사라진다.

### 아크테릭스는 시즌마다 상품코드가 바뀐다

원본 폴더 `아크테릭스/남성/Beta Jacket Men's` 안에 두 시즌 이미지가 함께 있다.

```
F26-X000010878-Beta-Jacket-Black-Front-View.avif    ← 카탈로그가 물고 있는 코드
S26-X000010511-Beta-Jacket-Headwaters-Hood.avif     ← 사이트맵에 있는 코드
```

URL 은 코드 끝 4자리로 대조하는데(`-0878`), 사이트맵에 그 시즌 URL 이 아직 없으면
대조가 통째로 빗나가고 상품이 **조용히 조회 대상에서 빠진다.**

그래서 코드가 안 맞으면 `/{성별}/{상품명 슬러그}-4자리` 로 후보를 찾는다.
**후보가 둘 이상이면 고르지 않는다** — 시즌이 다른 두 URL 중 아무거나 집으면
엉뚱한 상품의 재고를 이 상품 것으로 보고하게 된다. 리포트의 "아직 못 받은 상품" 표에
후보를 링크로 띄우니, 사람이 하나를 골라 `data/supplier-urls.json` 에 적어 넣는다.

```json
"arcteryx-beta-jacket-men": { "url": "…/mens/beta-jacket-0868", "via": "manual" }
```

`via:"manual"` 로 적으면 `--fresh` 로 다시 해석해도 지워지지 않는다.

### 카탈로그에 없으면 수집되지 않는다

목록수집은 **상위 프로젝트 카탈로그에 등록된 상품만** 받는다. 등록이 안 된 상품은
목록 페이지에 링크가 보여도 걸러진다 — 그래서 알림이 등록된 상품명을 함께 보여 준다.
"찾는 상품이 이 목록에 없으면 카탈로그에 등록되지 않은 것"이다.

원본 폴더가 규칙을 벗어나면 임포터가 상품을 통째로 건너뛴다. 이제 이유를 찍는다.

| 원본 상태 | 결과 |
|---|---|
| 색상 폴더 없이 이미지가 상품 폴더에 바로 있음 | **카탈로그에 안 생김** — 색상명 폴더를 만들어 옮겨라 |
| `details.txt` 없음 / 가격(`218CAD`) 없음 | **카탈로그에 안 생김** |
| `details.txt` 에 `Style Number` 없음 | 카탈로그엔 생기지만 **재고 조회 대상에서 빠짐** (SKU 가 `POLO-…` 가 된다) |

### 실패는 품절이 아니다

차단·마크업 변경으로 수집이 실패하면 `error` 로 분리해 보고하고, variant 를 0개로 두지 않는다.
실패를 품절로 읽으면 멀쩡한 상품이 판매 중지되고, 마지막 성공값으로 계속 팔면
주문 후 매입 실패로 이어진다 (PROJECT.md §6.3 5번).

```bash
npm run doctor                       # ① 엔드포인트 생존 확인 — 항상 먼저
```

| 옵션 | 뜻 |
|---|---|
| `--brand=<key[,key]>` | `arcteryx tommy polo canadagoose lululemon coach tumi`. 기본 전체 |
| `--limit=<n>` | 브랜드당 수집 상품 수 (기본 25) |
| `--new` | 최근 120일 내 신제품만 |
| `--fresh` | 캐시 무시 |
| `--no-signals` | 네이버 인기도 신호 생략 |
| `--no-kr` | 한국 가격 수집 생략 |
| `--watch[=파일]` | 재고 조회 대상을 URL 목록으로 지정 (기본 `watchlist.txt`) |
| `--import[=디렉터리]` | 북마클릿 수집 파일을 읽는다 (기본 다운로드 폴더) |

산출물은 `data/` 에 세 벌로 떨어진다 — 사람이 읽는 `.md`, 엑셀용 `.csv`, 재처리용 `.json`.

## 설계 판단

**왜 커뮤니티를 직접 긁지 않는가**
더쿠·디시·클리앙 직접 크롤링은 약관상 회색지대이고 노이즈가 크다. 네이버 검색 API의
블로그·카페 문서 수는 공식·무료·합법이면서 국내 언급량의 대리 지표로 충분히 기능한다.

**왜 브랜드별 CSS 셀렉터를 7벌 만들지 않는가**
7개 브랜드는 서로 다른 커머스 플랫폼 위에 있지만 SEO 때문에 대부분 schema.org
`Product`/`ProductGroup`을 심는다. 셀렉터는 분기마다 깨지지만 이 마크업은 SEO 자산이라
잘 바뀌지 않는다. 그래서 JSON-LD를 1순위로 두고 실패한 브랜드만 개별 처리한다.

**왜 카테고리 페이지 대신 사이트맵인가**
무한 스크롤을 긁는 것보다 상대 서버에 훨씬 가볍고, `lastmod`라는 신제품 신호를 덤으로 준다.
정렬 전에 잘라내지 않는다 — 그러면 "신제품"이 카탈로그 앞부분의 최신일 뿐이게 된다.

**인기도를 언급량만으로 재지 않는 이유**
"최근 1~2년 인기"를 물었으므로 총량만 보면 오래된 스테디셀러가 이긴다.
언급량 30% + 검색 증가세 30% + 최신성 20% + 유통폭 20%로 나눠 신규 부상을 잡아낸다.

**정가와 세일가를 반드시 분리한다**
코치는 `ProductGroup.offers`에 정가(CA$360)를, variant에 세일가(CA$180)를 싣는다.
최저가만 보면 "48% 싸다"가 사실은 특정 컬러웨이 세일이라는 걸 놓친다. 매입 판단이
달라지므로 리포트에 정가를 함께 적는다.

## 프로젝트 규칙과의 연결

- **통합 단일가** — 리포트의 원가(CAD)·마진·환율은 운영 내부 데이터다. 스토어에 노출하지 않는다 (CLAUDE.md 규칙 1)
- **정수 금액** — KRW는 원 단위 정수, CAD는 cent 단위 정수. 파싱 단계에서 float을 만들지 않는다 (규칙 2)
- **판매가 산출** — 앱의 `src/lib/pricing` 을 그대로 재사용한다. 계산 로직을 두 곳에 두지 않는다 (PROJECT.md §5)
- **원산지** — `originCountryHint` 는 페이지 텍스트에서 긁은 참고값이다.
  CKFTA 판정은 실물 라벨 확인 후에만 한다 (규칙 5)
- **정중한 크롤링** — robots.txt 준수, 호스트별 지연 2.5초·동시성 2, 429는 15초부터 지수 백오프.
  랄프로렌은 robots가 `*/search*`를 막으므로 검색 경로를 쓰지 않는다 (규칙 8)
- **한글 경로** — Node 스크립트는 `new URL().pathname` 대신 `fileURLToPath` 를 쓴다

## 구조

```
src/
  config/brands.ts     브랜드 레지스트리 — 엔드포인트·URL 패턴을 여기 한 곳에 모은다
  core/                politeness(robots·지연·백오프) · fetcher · browser · cache
  extract/             jsonld · sitemap · price · blockpage   ← 사이트 무관 순수 추출기
  adapters/generic.ts  사이트맵 + JSON-LD 범용 어댑터 (7개 브랜드 중 6개 커버)
  signals/             네이버 API 클라이언트 + 인기도 점수(순수 함수)
  match/               상품명 정규화 · CA↔KR 매칭(순수 함수)
  stock/               재고 조회 — 카탈로그 대조 · 사이즈·색상 정규화 · 변화 감지 · html/md/csv 리포트
  report/              markdown · csv
  pipeline.ts          오케스트레이션
```

계산·정규화·점수·차단판별·재고대조는 전부 순수 함수로 두고 단위 테스트를 붙였다 (`npm test`, 203개).

## 알려진 한계

**4개 브랜드는 봇 차단으로 자동 수집이 불가능하다** (룰루레몬·캐나다구스·투미, 폴로 CA).
→ **북마클릿(반자동)으로 수집한다.** 위 "차단 브랜드는 반자동으로" 절 참조.

실측 기록 (2026-08-28):

- **헤드리스 여부는 무관하다.** WSLg 로 실제 창을 띄운 브라우저(`headless:false`)로도
  폴로·캐나다구스는 결과가 동일했다(각각 PerimeterX 캡차 9.7KB, Kasada 748바이트).
- **룰루레몬은 첫 요청만 통과한다.** 사이트맵 200건 확보 후 PDP 1건은 색상·사이즈·재고까지
  정상 수집됐으나, 이후 요청부터 본문 218바이트 껍데기만 돌아온다.
  12초 간격으로 늦춰도 동일했다 — 속도가 아니라 세션/IP 단위 잠금이다.
- **투미는 연결 자체가 안 된다** (HTTP·브라우저 모두 타임아웃).

자동화를 계속 밀 경우의 선택지:

1. **브랜드 제휴/어필리에이트 피드** — 룰루레몬·랄프로렌은 Rakuten Advertising 에서
   상품 피드를 제공한다. 다만 갱신이 하루 1회라 §6.5 6시간 게이트에 미달하고,
   어필리에이트 약관이 자사 커머스 목적 사용을 제한하는 경우가 많다. 신청 전 조항 확인 필수.
2. **상용 언블로킹 프록시** — Bright Data Web Unlocker 기준 $1.50/1K.
   3개 브랜드 60 SKU 를 §6.4 주기로 돌리면 월 25,650회 ≈ $38. 200 SKU 면 약 $130.
   단 사이트 약관 위반이다.

그 밖에:

- **국내 최저가 축이 없다.** 네이버 쇼핑 검색 API 종료(2026-07-31) 이후
  가격을 주는 공개 API 가 없다. 대체 소스가 생기면 `lookupKrLowest()` 하나만 채우면 된다.
- **이름 유사도 매칭(신뢰도 1.0 미만)은 사람이 확인해야 한다.** 색상·시즌 차이를 구분하지 못한다.
- 재고는 리포트 생성 시점 값이다. 실제 판매 개시 전에는 §6.5 신선도 게이트(6시간)를 통과해야 한다.
