# 06 — `/orders/lookup` 비회원 주문 조회

> 비회원 주문을 허용하는 이상 **1급 동선**이다. 헤더에 상시 노출 (IA §2).
> **보안 제약이 디자인을 규정하는 유일한 화면** (IA §5-2). 셸: [00-shell.md](00-shell.md)

## 0. 이 화면이 하는 일

주문번호 + 연락처로 `/orders/[orderNo]`에 도달시킨다.
동시에 **열거 공격으로 타인 주문의 존재를 알아낼 수 없게 만든다.**

## 2. 정보 계층

```
1. 무엇을 하는 화면인가   30px/700 제목 + 15/400 한 줄
2. 무엇이 필요한가       두 필드. 그 이상 묻지 않는다
3. 어디서 찾는가         각 필드 아래 12/400 muted 헬퍼 — 여기가 이탈 방어점이다
4. 조회하기
5. 막혔을 때의 출구      1:1 문의 · 로그인
```

- **필드는 두 개뿐이다.** 이름·주소를 추가로 묻지 않는다. 물을수록 열거 공격의 정보원이 늘어난다.
- 캡차·이메일 인증 단계를 넣지 않는다. rate limit이 서버 쪽 방어다.

| | Mobile <768 | Tablet 768–1024 | Desktop 1024+ |
|---|---|---|---|
| 폼 폭 | 100% (마진 20px) | 480px 중앙 | 480px 중앙 |

- 주문번호 필드는 모바일에서 `inputmode="text"` + `autocapitalize="characters"`. 숫자 키패드를 강제하지 않는다(영문 포함 형식).
- 연락처 필드는 이메일/전화 겸용이므로 `inputmode="text"`. `type="tel"`을 쓰면 이메일 입력이 불편해진다.

## 5. 상태 5종 — §14 규칙 적용

### 5-1. Empty
- **초기 상태가 곧 빈 상태다.** 두 필드가 비어 있는 것이 정상 진입 화면이다.
- 별도의 empty 일러스트·문구를 만들지 않는다.

### 5-2. Skeleton
- **이 화면에는 스켈레톤이 없다.** 서버에서 즉시 렌더되는 정적 폼이다.
- 스켈레톤을 깔면 두 번 그려지고 CLS가 발생한다.

### 5-3. Loading
```
┌───────────────────────────────────────┐
│            조회하기                    │  opacity 0.4, 라벨 유지
└───────────────────────────────────────┘
```
- CTA opacity 0.4 + 두 필드 입력 잠금. 스피너 아이콘 없음.
- **최소 표시 시간 400ms를 강제한다.** 즉시 실패가 돌아오면 응답 시간 차이로 "주문번호는 존재하나 연락처가 틀림"을 유추할 수 있다 → **타이밍 사이드채널 차단** (IA §5-2 확장).
- 성공 시 `motion-page` 350ms로 `/orders/[orderNo]` 전환.

### 5-4. Error — 이 화면의 핵심

> **§5-2 보안 요건: 실패 응답을 구분하지 않는다.**
> `주문번호 없음`과 `연락처 불일치`는 **같은 문구, 같은 위치, 같은 지연**을 쓴다.

```
┌───────────────────────────────────────┐
│ R260826-7F3K9Q                        │  ← 보더 1px #ed0038 (두 필드 모두)
└───────────────────────────────────────┘
┌───────────────────────────────────────┐
│ 010-****-****                         │  ← 보더 1px #ed0038
└───────────────────────────────────────┘
주문번호와 연락처가 맞지 않아요. 다시 확인해 주세요.   13px / 400 / #ed0038
```

| 경우 | 처리 |
|---|---|
| 주문번호 없음 | ↑ 위 문구 그대로. **"없는 주문번호예요"라고 쓰지 않는다** |
| 연락처 불일치 | ↑ **동일 문구.** 어느 필드가 틀렸는지 표시하지 않는다 |
| 형식 오류 (제출 전 클라이언트 검증) | 해당 필드에만 13px/400 `#ed0038` — `주문번호 형식이 달라요` / `연락처를 다시 확인해 주세요`. 이건 서버에 가기 전이므로 구분해도 안전하다 |
| **rate limit 도달** | 15/400 `#000000` 한 줄 `잠시 후에 다시 시도해 주세요.` + 12/400 muted `1:1 문의로도 확인해 드려요.` 남은 시간을 카운트다운으로 표시하지 않는다 (§10 카운트다운 금지) |
| 네트워크 실패 | 토스트 `#000000`/`#ffffff` 14/400/2px/하단 중앙/3초 |
| 서버 장애 | 화면 차단 — 흰 화면, 16px/700 한 줄, 고스트 `다시 시도하기` |

- 실패 횟수를 화면에 노출하지 않는다 (`3회 남았어요` 금지) — 공격자에게 예산을 알려주는 셈이다.
- 에러는 색만으로 전달하지 않는다. `#ed0038` 보더 + 텍스트를 항상 함께 (PRODUCT.md 접근성).
- 에러 텍스트에 `role="alert"` + `aria-live="polite"`.

### 5-5. Success
- **이 화면에 성공 UI가 없다.** 성공 = 즉시 `/orders/[orderNo]` 라우트 전환.
- 초록 체크마크·"조회되었습니다" 중간 화면 금지.
- 조회 세션은 서버 쿠키로 부여한다. 주문번호가 URL에 노출되므로 **세션 없이 URL만으로는 열리지 않아야 한다** (IA §5-2).

## 6. 모션
- 에러 텍스트 등장: opacity 0→1 · `motion-quick`. **흔들기 금지.**
- 라우트 전환: `motion-page` 350ms.
- CTA 호버: 배경 4% 밝아짐 · `motion-quick`.
- reduce-motion: 전부 instant.
