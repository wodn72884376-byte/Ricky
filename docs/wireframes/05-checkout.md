그리고 하나를 반드시 보여준다 — **결제 전 예상 세액** (PRODUCT.md 불안 2).

## 2. 정보 계층

```
1. 누가 받는가      주문자 → 받는 분 → 주소
2. 통관 자격        PCCC. 안내를 필드 위에 먼저 놓는다 — 입력하고 나서 틀리면 늦다
3. 금액             요약 열에서 상시 보인다 (sticky). 결제 버튼 라벨에도 금액을 박는다
4. 동의             약관 체크
5. 결제             유일한 반전 블랙
6. 각주             세액이 결제 금액에 포함되지 않는다는 사실 — 마지막에 한 번 더
```

**§12-8 적용:** 요약의 세액은 `예상`, `약`으로 표기하고, 결제 금액과 명확히 분리한다.
결제 예정 금액(855,000원)에 세액(106,000원)은 **들어있지 않다.** 이 구분이 흐려지면 DDU 분쟁이 난다.

**폼 필드 순서 = 통관 서류 순서.** 이름·연락처·주소·PCCC가 세관에서 대조되므로 화면 순서를 같게 둔다.

## 4. 반응형

| | Mobile <768 | Tablet 768–1024 | Desktop 1024+ |
|---|---|---|---|
| 레이아웃 | 1열 — **요약을 맨 위 접힌 상태로** (`855,000원 ▾`) 그 아래 폼 | 1열 (요약 상단 펼침) | 2열 7:5, 요약 sticky |
| 이름/연락처 | 세로 스택 | 2열 | 2열 |
| 우편번호+찾기 | 가로 유지 (2:3) | 가로 | 가로 |
| 결제 CTA | **하단 고정 바** h52 | 인라인 | 인라인 |
| 폼 필드 높이 | 52px 유지 | 52px | 52px |
| 지면 마진 | 20px | 32px | 48px |

- **모바일에서 요약을 접는다.** 폼이 길어 요약이 화면 밖으로 밀리는데, 하단 고정 바가 금액을 항상 들고 있으므로 sticky 요약은 중복이다.
- 모바일 하단 고정 바: `855,000원` 15/700 + `결제하기` 반전 블랙 h52. 상단 보더 `1px #c4c4c4`.
- 플로팅 `1:1 문의`는 이 바 위로 24px. **체크아웃에서 제거하지 않는다** — 여기가 문의가 가장 필요한 지점이다.

## 5. 상태 5종 — §14 규칙 적용

### 5-1. Empty
- **장바구니가 비어 있으면 이 화면에 진입할 수 없다.** `/cart`로 즉시 리다이렉트.
- 리다이렉트 대신 빈 체크아웃을 렌더하지 않는다.
- 세션 만료로 주문 컨텍스트가 사라진 경우: 흰 지면 16px/700 `주문 정보가 만료됐어요` + 고스트 `장바구니로 돌아가기`.

### 5-2. Skeleton
- 요약 열의 라인 아이템 자리에만 `#f5f5f5` 블록 (썸네일 + 텍스트 2행). **금액은 `--`.**
- **폼 필드에는 스켈레톤을 쓰지 않는다.** 빈 필드가 곧 최종 상태다 — 스켈레톤을 깔면 두 번 그려진다.
- Stripe 엘리먼트 자리: `1px solid #c4c4c4` 빈 박스 h52, 내부 텍스트 없음. 1.0s 페이드 펄스, 시머 금지.

### 5-3. Loading
| 경우 | 처리 |
|---|---|
| 주소 검색 팝업 열림 | 버튼 opacity 0.4, 라벨 유지 |
| 세액 재계산 (주소 입력 후) | 요약의 세액 자리 12/400 muted `계산 중이에요`. **`0원`으로 깜빡이지 않는다** |
| 재고 재검증 (제출 직전) | CTA opacity 0.4, 라벨 유지. 스피너 아이콘 없음 |
| 결제 처리 중 | CTA opacity 0.4 + **폼 전체 입력 잠금**. 오버레이 스크림 금지 — 사용자가 금액을 계속 볼 수 있어야 한다 |
| 3DS 리디렉트 | 화면 전환 `motion-page`. 중간 로딩 화면을 만들지 않는다 |

### 5-4. Error — 이 화면의 핵심

**인라인 필드 에러** (§14 Error 인라인 그대로)
```
개인통관고유부호
┌───────────────────────────────────┐
│ P12345                            │   ← 보더 1px #ed0038
└───────────────────────────────────┘
개인통관고유부호는 P로 시작하는 13자리예요.   13px / 400 / #ed0038
```
| 필드 | 에러 문구 (13px/400 `#ed0038`, 한 문장, `~요` 종결) |
|---|---|
| 이메일 | `이메일 주소를 다시 확인해 주세요.` |
| 휴대폰 번호 | `휴대폰 번호를 다시 확인해 주세요.` |
| 받는 분 이름 | `받는 분 이름을 입력해 주세요.` |
| 우편번호/주소 | `주소 찾기로 주소를 선택해 주세요.` |
| PCCC | `개인통관고유부호는 P로 시작하는 13자리예요.` |
| 동의 | `주문 내용 확인과 결제 동의가 필요해요.` |

**폼 레벨 에러**
| 경우 | 처리 |
|---|---|
| 결제 실패 | CTA 위 15/400 `#ed0038` 한 줄 + 카드사 사유. 토스트가 아니라 **인라인** — 3초 뒤 사라지면 안 되는 정보다 |
| 재고 소진 (제출 시점) | 요약의 해당 라인 muted 강등 + 12/400 muted `방금 품절됐어요`. CTA disabled(opacity 0.4). 결제를 진행시키지 않는다 |
| 가격 변동 (제출 시점) | 요약 금액 갱신 + 12/400 muted `가격이 바뀌어서 금액을 다시 계산했어요. 확인하고 결제해 주세요.` CTA를 **한 번 더 눌러야** 진행 |
| 세액 계산 실패 | 요약 세액 자리 12/400 muted `예상 세액을 계산하지 못했어요. 통관 시점에 확정돼요.` **결제는 막지 않는다** — 세액은 RICKY가 받는 돈이 아니다 |
| 네트워크 단절 | 토스트 `#000000`/`#ffffff` 14/400/2px/하단 중앙/3초. 폼 입력값은 유지 |

- **에러 요약 배너를 폼 상단에 만들지 않는다.** 인라인 + 첫 에러 필드로 포커스 이동(`ease-standard`)이 이 시스템의 방식이다.
- 에러는 색만으로 전달하지 않는다 — 항상 텍스트를 동반한다 (PRODUCT.md 접근성).
- `aria-invalid` + `aria-describedby`로 에러 텍스트를 필드에 연결한다.

### 5-5. Success
- 성공 시 **즉시 `/checkout/complete/[orderNo]`로 라우트 전환** (`motion-page` 350ms).
- 이 화면에 성공 UI를 두지 않는다. 초록 체크마크·컨페티 금지.
- 완료 화면 규격 (§14 Success 주문 완료):
```
   주문이 접수됐어요                      15 / 400
   R260826-7F3K9Q                        22px / 700  ← 주문번호
   ── 20px ──
   Beta LT 자켓 블랙 M                    15 / 400
   Align 팬츠 25" 블랙                    15 / 400
   ── 16px ──
   결제 금액              855,000원        22px / 700 tabular
   예상 관세·부가세       약 106,000원      15 / 400
   개인통관고유부호       P1234****9012    15 / 400  ← 마스킹
   ── 24px ──
   [ 주문 내역 보기 > ]                    고스트 h52
```
  → `/orders/[orderNo]`로 **즉시 진입 가능**하게 한다. 주문번호를 기억하게 만들지 않는다 (IA §3).

## 6. 모션
- 섹션 간 포커스 이동: `ease-standard`.
- 아코디언(계산 자세히): `ease-standard`.
- 에러 텍스트 등장: opacity 0→1 `motion-quick`. **흔들기(shake) 금지** — 겁주지 않는다.
- 라우트 전환: `motion-page` 350ms.
- reduce-motion: 전부 instant.
